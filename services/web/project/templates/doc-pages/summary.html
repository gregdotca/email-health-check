At a glance

The summary (sometimes called the Exec Summary) is the verdict on a domain's email in three lines. It's the first box in every report, and the emailed report also attaches it as a picture so it can be shared.

Can receive email
The domain has MX records naming its mail servers, so mail (including the report) can be delivered to it.
Is authenticated
SPF decides yes or no. DKIM and DMARC are named when they pass too, and flagged when they're set up but failing.

Marks

  • {{ true|mark }} Passed Nothing to do.
  • {{ false|mark }} Failed Needs fixing.
  • {{ "warn"|mark }} Problem A problem was found that needs attention.
  • {{ none|mark }} Unknown Couldn't be checked, for example because of a DNS error.

On this website the status is never All Tests Passed, because only the email can confirm the report was delivered (see The website and the email).

Can send email

{{ true|mark }}The test message reached the check. If you're reading a report, this is always the case.

Can receive email

{{ true|mark }}The domain has MX records, and the emailed report is proof that mail reaches it.
{{ false|mark }}The domain has no MX records, or a "null MX" record saying it accepts no mail. (Some senders fall back to a domain's address records when it has no MX records, but that isn't something to rely on, so it isn't tested.)
{{ none|mark }}A DNS error stopped the MX lookup. Also shown on this website when the domain has MX records, because only the email can confirm the reply arrived.

Is authenticated

SPF alone decides yes or no. A domain with no DKIM or DMARC at all can still pass. When SPF passes, the line names everything that passed, for example "Yes (SPF, DKIM, DMARC)". DKIM is only named when a signature for the From: domain passes (a subdomain such as mail.example.com counts for example.com).

{{ true|mark }}SPF passes, nothing that's set up is failing, and every check finished.
{{ false|mark }}SPF doesn't pass: none, neutral, softfail, fail or permerror. This outweighs everything else.
{{ "warn"|mark }}SPF doesn't fail, but a problem was found:
  • a DKIM signature or DMARC fails, or
  • the message is DKIM-signed only by another domain (usually the mail service's), not the From: domain, or
  • DMARC is set up but the message has no DKIM signature, or
  • the SPF or DMARC record has a "Problem:" note.
{{ none|mark }}No problem was found, but a check couldn't finish: a DNS error (including one that stopped SPF), more than {{ v.max_signatures }} DKIM signatures (the rest aren't checked), or an SPF record whose DNS lookups couldn't all be counted.

Whatever the mark, the line lists what it found, for example "Yes (SPF), but no DKIM signature for example.com". When the test was sent by logging in to the receiving mail server, this line shows {{ none|mark }}, or {{ "warn"|mark }} if a record or signature has a problem anyway: see Troubleshooting.
