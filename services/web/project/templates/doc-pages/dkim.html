What it proves

DKIM (DomainKeys Identified Mail) adds a signature to each message. The sending domain publishes the matching public key in DNS, at selector._domainkey.domain. A valid signature shows that the message was signed with that domain's key, and that the parts it signed (the headers it lists and the text) weren't changed on the way, apart from small changes to spacing that DKIM allows.

A message can carry several signatures, for example one from your domain and one from your mail service. The check verifies the first {{ v.max_signatures }}, and if there are more, the summary says how many weren't checked.

The box's own result is pass if any signature passes, otherwise the first signature's result.

RSA keys (at least 1,024 bits, as smaller ones fail) and Ed25519 keys are supported. To keep checks quick and safe, a signature is a permerror if its RSA key is over 8,192 bits, if its h= list names more than 64 headers (repeats count), or if the message has more than 1,000 header fields. A signature also fails if the key's own tags rule it out: h= (the hash algorithms the key may be used with) or t=s (the signature's i= identity must be at the domain itself, not a subdomain).

A signature with an l= tag only covers the first part of the text, so text added after that part doesn't break it. Most services don't use l=.

What the box shows

One entry per signature:

signed by
The domain the signature is for (its d= tag), with its result.
Selector
Where the key was looked up in DNS.
Reason
For a signature that didn't pass: the exact reason given by the check.

Your domain's signature

Receivers, and DMARC, care most about a signature for the domain in the From: address. A signature only for your mail service's domain says the service sent the message, not that your domain did.

So the summary's "Is authenticated" line only names DKIM when a signature for your domain passes, and flags a message signed only by another domain ({{ "warn"|mark }}, unless SPF has already made it {{ false|mark }}). For the summary, any domain under the same registered domain counts: example.com, mail.example.com and news.example.com all count for each other. DMARC can be stricter (see Alignment).

Fixing it

  • none, or signed only by your mail service: turn on DKIM signing for your own domain in the mail service's settings. It gives you one or more DNS records (usually CNAME or TXT records under _domainkey) to publish.
  • permerror: the key record named by the selector is missing or malformed. Check that the record your service gave you is published exactly, under the right name.
  • fail: the message was changed after signing (often by a forwarding service, a mailing list or a security gateway that adds a footer), or the published key doesn't match the one the server signs with. Send the test directly, and check that the key in DNS is the current one.
  • rsa-sha1: switch the signing to rsa-sha256 in your mail server or service.
  • temperror: send another test. If it keeps happening, check the domain's DNS servers.
