No report arrived

Give it a couple of minutes, and check your spam folder{% if v.report_from %} for an email from {{ v.report_from }}{% endif %}. Then {% if v.public_url %}look the report up online with the address you sent from{% else %}work through the list below{% endif %}:

  • The report online says no report was emailed. Usually the test was one that isn't answered (see Messages that aren't answered): send it straight from a mailbox instead. It can also mean a sending limit was reached, or the report couldn't be sent. If neither explains it, ask whoever runs this service to check its logs.
  • The report is online, but the email never came. Your own mail system may have filtered or rejected the reply: check your spam folder and filtering, and that the domain has MX records. The report is saved before the email is sent, so the email may also still be waiting to be retried.
  • There's no report online either. The test may not have been checked yet, its report may already have expired, or it never reached the check. Make sure it was sent to {{ m.address(v) }} and didn't bounce. A message the receiving mail server's spam filter rejects or deletes never arrives, so a test that looks very much like spam may not get through. Messages over {{ v.max_mb }} MB are deleted without a reply.

No report on the website

  • Enter the address the test was sent from, not the test address.
  • Reports expire {{ v.viewed_minutes }} minutes after they're first shown, and after {{ v.unviewed_hours }} hours if nobody looks. Viewing one also deletes older reports for that address. Send a new test.
  • The test may not have been checked yet: wait {{ m.within(v) }} and try again.
  • "Enter the email address you sent the test from." means what you entered wasn't an email address: enter just the address, without a name or angle brackets.
  • "Please use the form on this page." means the form was sent from another website, which is refused. Open this website directly and use its form.
  • "The service is busy. Please try again in a moment." means the website couldn't reach its database just then. Try again shortly.
  • "Too many lookups from your network" means the lookup limit ({{ v.lookups_minute }} a minute, {{ v.lookups_hour }} an hour) was reached. Wait and try again: the hourly limit can take up to an hour to clear.

The report says Incomplete

Nothing failed, but something couldn't be checked: usually a temporary DNS error, so send another test. If it keeps happening, check that the domain's DNS servers are answering. Two other causes:

  • The message has more than {{ v.max_signatures }} DKIM signatures, so not all of them were checked.
  • The SPF record's DNS lookups couldn't all be counted (for example, because of macros or a loop).

On this website the status is never higher than Incomplete, and that's expected (see The website and the email).

Sent by logging in to the receiving server

If your domain's mail is hosted on the same mail server that receives the tests, a test you send is handed over by logging in to that server, not delivered from another mail server the way your mail reaches everyone else. The report then shows a note, and its "Is authenticated" line shows {{ none|mark }}: SPF is checked against the server that logged in, and that path isn't DKIM-signed, so the results don't show what other receivers would see. Problems with the records themselves are still listed (and make it {{ "warn"|mark }}).

To get a full report for the same domain, send from an address at that domain through a different outgoing mail service, one that delivers to the receiving server like any other mail server. (Sending from an unrelated address, such as a personal one, tests that address's domain instead.)
