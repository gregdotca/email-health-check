What it proves

A PTR record (reverse DNS) gives an IP address a name, such as mail.example.com. The check looks up the name for the server that delivered the test, then looks that name up again to make sure it points back to the same IP address. This is called forward-confirmed reverse DNS. If the IP address has several PTR names, the first five are tried, and one that points back is enough. IPv6 addresses are checked the same way.

Many receiving servers expect a mail server to have it, and treat mail from an IP address without it as suspicious. It's about the sending server, not the domain, so it isn't part of the summary.

If you send through a mail provider, its servers are the ones checked. Their reverse DNS is the provider's job, not yours.

Fixing it

  • none: ask whoever controls the IP address (your hosting or network provider) to set a PTR record for it, using the name your mail server uses.
  • mismatch: add an A (or AAAA) record so the PTR name points back to the same IP address, or change the PTR record to a name that does.
  • temperror: send another test. If it keeps happening, check that the DNS servers for the IP address and the name are answering.
