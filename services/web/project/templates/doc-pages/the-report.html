The report reads from top to bottom: first the verdict, then the message it's about, then one box per check. Explanations only appear for checks that don't pass, so a healthy domain's report is short.

The email

The report arrives as a reply to your test, from {{ app_title }}, with the subject Report for yourdomain.com. It has a plain-text and an HTML version with the same content, and two attachments (see Attachments). {% if v.public_url %}It ends with a link to the same report on this website.{% endif %}

It's sent as a reply, so most mail programs show it in the same conversation as your test, and it's marked as an automatic reply so other auto-responders (such as out-of-office replies) don't answer it.

Times are shown in the {{ v.timezone }} time zone, like this: {{ v.example_time }}.

The summary

The first box names the domain being tested (the domain of the From: address), gives an overall status, and answers three questions: can the domain send email, can it receive email, and is its mail authenticated.

Message details

The next box, lightly highlighted, says which message the report is about:

Subject: Testing our mail setup

Date Received

you@example.com
Sending IP
192.0.2.25 (mail.example.com)
PTR: pass SPF: pass DKIM: pass DMARC: pass
Subject
The test message's subject, decoded if it was encoded.
Date Received
When the receiving mail server accepted it (or, if that isn't known, when it was checked).
From Address
The address in the From: header (the address only, without a display name). This is the domain the summary is about, and where the report is sent.
Sending IP
The server that delivered the test to the receiving mail server, with its verified name in brackets when it has one. This is the server SPF and PTR are checked for.

The row of badges at the bottom gives each check's result in one word.

Result badges are coloured by how serious they are:

ColourMeaning
passThe check passed.
softfailA weak failure, or a temporary error worth trying again (softfail, temperror).
failThe check failed or the record is broken (fail, permerror, mismatch).
noneNothing to check, or no verdict (none, neutral, not checked).

Notes and problems

Two kinds of notes can appear, in yellow:

  • Notes in the message details box, about the test itself:
    • it was sent by logging in to the same mail server that received it, so the results don't show what other receivers would see (see Troubleshooting)
    • the receiving mail server's record of the delivery couldn't be found, so SPF and PTR weren't checked
    • the message doesn't have exactly one From: address, so DMARC doesn't apply
    • the message has no DKIM signature, or more than {{ v.max_signatures }} (only the first {{ v.max_signatures }} are checked)
  • "Problem:" notes in the SPF and DMARC boxes, when the record itself has a problem, even if this test passed. For example, an SPF record that's close to its limit of {{ v.max_lookups }} DNS lookups, or a DMARC record with an invalid policy.

If a message couldn't be checked at all, the report online says so in red instead of showing the checks, and no report is emailed. Very long values (a huge subject, say) are cut off and end in "…".
