What it proves

SPF (Sender Policy Framework) lets a domain publish, in a DNS TXT record, which servers may send its mail. A typical record looks like this:

v=spf1 include:_spf.mailservice.example.net ip4:192.0.2.25 -all

The check asks whether the server that delivered the test is allowed to send for the domain of the envelope sender (the Return-Path, where bounces go). That's often the same domain as the From: address, but a mail service may use its own. DMARC alignment is what ties SPF to the From: domain.

For a bounce (an empty envelope sender), SPF checks the name the sending server gave when it connected (its HELO name) instead.

SPF is what decides the summary's "Is authenticated" line.

ResultMeaning

"Not checked" means the server that delivered the test couldn't be identified, so there was nothing to check. SPF also allows at most two DNS lookups that find nothing ("void" lookups). More is a permerror even with fewer than {{ v.max_lookups }} lookups in all, and the Detail row says so. A check that takes longer than 20 seconds in all (slow or unanswered DNS) stops with temperror, and a term over 512 characters in the record, or in one it includes, is a permerror.

For a result other than pass or none: the exact reason given by the check.

Problem notes

The check looks at the whole record, not just the part this test needed. A record can pass for one server and still be broken for others, so these get a "Problem:" note even when the test passed:

  • Too many DNS lookups. Over {{ v.max_lookups }}, receivers give permerror for any server not matched within the first {{ v.max_lookups }}, so some of the domain's mail fails. {{ v.near_limit }} or {{ v.max_lookups }} gets a note too: there's little room left, so another include, or a change at a provider, could push it over.
  • A broken include or redirect. A domain the record includes has no SPF record, more than one, or one with a syntax error.

A "Problem:" note makes the summary's "Is authenticated" line {{ "warn"|mark }} (unless SPF has already made it {{ false|mark }}).

Fixing it

  • fail, softfail or neutral: add the sending server to the record. For a mail service, add the include: it gives in its setup instructions.
  • none: publish an SPF record listing every server and service that sends your mail, ending in -all or ~all.
  • permerror: fix the record's syntax, and make sure the domain has exactly one record starting v=spf1.
  • Too many lookups: remove includes for services you no longer use, replace a and mx with ip4:/ip6: ranges where they don't change, or move some mail to a subdomain with its own record.
  • temperror: send another test. If it keeps happening, check the domain's DNS servers.
