Terms

Alignment
Whether the domain that passed SPF or DKIM matches the From: domain. Relaxed alignment (the default) lets subdomains match. See DMARC.
DKIM
DomainKeys Identified Mail: a signature added to a message by the sending domain, checked against a public key in its DNS. See DKIM.
DMARC
A policy published by the From: domain saying what receivers should do with mail that doesn't pass SPF or DKIM for that domain. See DMARC.
DNS record
An entry in a domain's DNS. SPF, DKIM keys and DMARC are all TXT records, while MX and PTR records have their own types. Changes take effect once the old record's TTL (time to live) has passed.
Envelope sender
The address a sending server gives when it delivers a message, where bounces are sent. It's saved in the message as the Return-Path header. It can differ from the From: address, as mail services often use their own domain for it.
From: address
The sender address people see in their mail program. It's the domain DMARC protects and the one this report is about.
Headers
The lines at the top of a message (From:, Subject:, Received:, DKIM-Signature: and many more) that say who sent it and how it travelled. Most mail programs can show them ("Show original" or "View source").
HELO
The name a sending server gives when it connects. The sender chooses it, so it proves nothing on its own.
Mail service
A company that sends mail for your domain: your mailbox provider, a newsletter or marketing service, a ticket system. Each one sends from its own servers, so test each one separately. Its servers need to be in the SPF record of the envelope sender's domain (yours, unless the service uses its own), and it should sign with DKIM for your domain.
MX record
Names the servers that accept mail for a domain. A domain that receives mail should have them: the health check looks for them, and doesn't test the old fallback to a domain's address records. A "null MX" record says the domain accepts no mail at all.
Organizational domain
The registered domain a name belongs to: example.com for mail.example.com. Where domains are registered under a two-part ending, such as .co.uk, it has three parts.
PTR record (reverse DNS)
Gives an IP address a name. "Forward-confirmed" means that name also points back to the same IP address. See PTR.
Received: header
A line each mail server adds when it accepts a message, saying where it came from. Only the one added by the receiving mail server is trusted: anything older was written by the sender's side and could be forged.
Selector
The name a DKIM signature uses to say which key to look up, at selector._domainkey.domain. A domain can have several keys, one per selector.
SPF
Sender Policy Framework: a DNS record listing the servers allowed to send a domain's mail. See SPF.
temperror and permerror
A temperror is temporary, usually a DNS server that didn't answer: try again. A permerror is permanent: the record is broken and needs fixing.
