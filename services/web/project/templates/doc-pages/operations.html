Logs

docker compose logs -f poller
docker compose logs -f web

The logs show counts and reasons, never addresses: for each test, whether a report was sent and, if not, why. Each check of the mailbox handles up to {{ v.max_per_poll }} messages, and any more wait for the next one.

Updating

git pull
docker compose up -d --build

Check the changelog and .env.example for new settings first.

Data

The SQLite database lives in the Compose volume data. It only holds short-lived reports and rate-limit counters, which expire on their own, so it needs no backups. docker compose down -v removes it along with the containers.

Log messages

The service stops at startup
The log names the setting that's missing or invalid. Fix it in .env, then run docker compose up -d again.
Nothing in the log for a test
It may still be waiting for the next check of the mailbox, or it never reached the mailbox. IMAP error or connection error lines mean the poller can't log in or connect. It tries again after 30 seconds, or after 5 minutes when the server reports a failed login (AUTHENTICATIONFAILED), so a wrong password doesn't get its IP address blocked. Otherwise, check that the test was delivered (a spam filter on the receiving server may have rejected or deleted it).
no results email: …
The test was deliberately not answered. The reason says why:
  • envelope sender is at a different domain: the report only goes to the From: address when the envelope sender is at the same domain
  • automatic message, bulk or list message, mailing list message, bounce (empty envelope sender) or system or no-reply address: automatic mail is never answered
  • addressed to this tool: mail from the test address's own domain isn't answered
  • rate limit reached: too many reports to that address in the last hour or 24 hours, or to everyone in the last 24 hours (the MAIL_PER_* settings)
sending the results email failed …
The SMTP service refused the email or couldn't be reached. Temporary failures are retried {{ v.max_attempts - 1 }} times, at least {{ v.retry_schedule }} minutes apart. Test the login with the --check-smtp command in Setup.
Reports say the receiving mail server's record couldn't be found
TRUSTED_MX_HOSTS doesn't match the names your server writes after by in its Received: headers.
analysis failed …
Something in the message couldn't be checked. It's deleted without a report email. With the website on, a short report saying so is kept online.
handling a message failed …
An unexpected error interrupted the work on a message, and the poller deleted it. A report may already have been saved online or emailed: look it up, and check for a sent a results email line.
message too large …
A test over {{ v.max_mb }} MB was deleted without being checked.
Other warnings
  • saving the result for the web page failed: the report can't be looked up online (it's still emailed, if the reply rules and limits allow). Check the database's storage.
  • updating the saved result failed: the report online may wrongly say a report was emailed.
  • checking the sending limits failed …; will retry: the database was busy, so the message is kept and tried again.
  • building the results email failed: the email couldn't be put together. It isn't retried, and the message is deleted.
  • drawing the summary image failed: the email was sent without the picture.
  • the email was accepted, but closing the connection failed: the email was sent, and it isn't sent again.
  • couldn't list the mail folders, couldn't get a message's size, couldn't flag a handled message for deletion, expunge failed: a mail server hiccup. The poller tries again on the next check. It remembers what it has answered only while it runs, so a restart before a message is deleted can answer it again.
  • cleaning up expired results failed: expired reports can't be looked up, but stay in the database until a clean-up succeeds.
Reports land in spam
The sending domain's SPF and DKIM need to include your SMTP service.
