Send the test

  1. Pick a mailbox on the domain you want to check, for example postmaster@example.com or your own address there.
  2. Send an email from it to {{ m.address(v) }}. Any subject and body text will do (though some mail programs won't send a message with a blank subject).{{ m.address_note(v) }}
  3. Wait for the reply. The test address is checked {% if v.poll_seconds %}every {{ v.poll_seconds }} seconds{% else %}regularly{% endif %}, so the report usually arrives within {{ m.within(v) }}.

Send the test the way your real mail goes out. To check mail sent by a newsletter service, a ticket system or a website's contact form, send the test through that service: each one sends from its own servers, so each one can pass or fail on its own. Such services often add headers that mean no report is emailed (see below){% if v.public_url %}, but the report can still be looked up online{% endif %}.

A test can be delivered to the test address's spam folder: that's fine, it's checked too. Messages over {{ v.max_mb }} MB are deleted without a reply, so keep the test small.

Who gets the report

The report goes to the message's From: address, the one people see, but only when the envelope sender (the Return-Path, where bounces go) is at the same domain. Subdomains count as the same domain, so a Return-Path at bounces.example.com matches a From: address at example.com. This keeps reports from going to unrelated domains, but it doesn't prove who sent the test (both addresses can be forged), which is why there are sending limits too.

Failing SPF, DKIM or DMARC never stops the reply: that's exactly what you want to know. But a reply sent to a domain whose own mail setup is badly broken may itself be delayed or filtered, so if it doesn't come, look the report up online.

Messages that aren't answered

Automatic mail never gets a reply, so that two automatic systems can't keep answering each other, and neither does mail the report couldn't safely be sent back to:

  • bounces (a message with an empty envelope sender)
  • automatic replies, such as out-of-office messages (an Auto-Submitted header saying anything other than no)
  • bulk and mailing-list mail (a Precedence header of bulk, list, junk or auto_reply, or a List-Id or List-Unsubscribe header, which most email marketing services add)
  • messages from system or no-reply addresses: {% for p in v.skip_local_parts %}{{ p }}@{{ ", " if not loop.last }}{% endfor %}
  • messages whose envelope sender is at a different domain from the From: address
  • messages from the test address's own domain, or from the address the reports are sent from
  • messages without exactly one From: address

postmaster@ is answered: it's a common address to test from.

A test that isn't answered is still checked{% if v.public_url %}, so you can look it up online{% endif %}.

How often you can test

To keep the service fair and stop it being used to send mail to others, there are limits on report emails:

  • {{ v.mail_hour }} reports an hour and {{ v.mail_day }} a day to any one address
  • {{ v.mail_total }} reports a day in total, from everyone

The limits count the last hour and the last 24 hours, not calendar days, and a report counts once it's been tried, even if it couldn't be delivered. Past a limit, tests are still checked but no report is emailed.

If sending a report fails for a temporary reason, it's tried again on later checks of the mailbox, at least {{ v.retry_schedule }} minutes apart, then given up. Retries don't count against the limits again.
