Requirements

  • A mailbox used only for tests, on a mail server that writes Exim-style Received: headers (see What's trusted), reachable over IMAP with TLS on port 993 (not configurable) with a username and password. The test address can be the mailbox's own address or an alias delivered into it.
  • An SMTP service to send the reports, with STARTTLS (usually port 587), or without TLS if SENDING_EMAIL_USE_TLS=False. Implicit TLS (usually port 465) isn't supported. Your sending domain's SPF and DKIM should include it, so the reports themselves are delivered.
  • Docker with Compose, on a host that can reach your IMAP and SMTP servers and make DNS lookups.
  • For the optional website: a hostname, and a reverse proxy (Caddy, nginx or similar) to serve it over HTTPS.

Use a dedicated mailbox. The poller checks and deletes every message in the folders it reads (old, already-read and sent to other aliases alike), and it doesn't pick out mail for the test address. With the website on, each one's headers can also be looked up for a while.

IMAP, and SMTP with STARTTLS, check the server's certificate. Logins use passwords (an app password, if your provider requires one), not OAuth. SENDING_EMAIL_USE_TLS=False turns off SMTP encryption, including for the login, so use it only for a trusted local relay.

Setup

  1. Get the code

    git clone https://github.com/gregdotca/email-health-check.git
cd email-health-check
cp .env.example .env

  2. Fill in .env

    Fill in the first section of .env: the mailbox, SMTP, TRUSTED_MX_HOSTS and website settings. Everything below it is already set to the defaults (all of them are described in Settings). For TRUSTED_MX_HOSTS, use the names your receiving server writes after by in the Received: headers of mail it accepts (usually its MX host names), including any backup MX. If you're not sure, send yourself a message and look at its headers.

  3. Check the settings

    This checks the settings, then connects to the SMTP server (starting TLS and logging in, if set up), without sending anything:

    docker compose run --rm --build poller python -m healthcheck.poller --check-smtp

    A missing or invalid setting stops it with a message naming the setting. It doesn't test the IMAP login: the poller's log shows that once it's running.

  4. Start it

    docker compose up -d --build

  5. Send a test

    Send an email to the test address. The report should arrive within a minute or so. If it doesn't, see Log messages.

To try it without changing anything, set DRY_RUN=True: messages are checked (and saved, with the website), but nothing is sent, flagged or deleted.

With or without the website

With the website
Set PUBLIC_URL (for example https://check.example.com) and COMPOSE_PROFILES=web, and point your reverse proxy at WEB_BIND (default 127.0.0.1:8080). Keep WEB_BIND off the public internet: the proxy is the way in. These docs are on at /docs/ unless you set DOCS_ENABLED=False.
Email-only
Leave PUBLIC_URL and COMPOSE_PROFILES empty. Only the poller runs, the emails have no link to a website, and no reports are kept.

The two settings do different jobs. PUBLIC_URL tells the app there's a website, so the emails link to it and reports are kept for looking up. COMPOSE_PROFILES is Docker Compose's own setting: the website's container is in a Compose profile named web, which Compose only starts when COMPOSE_PROFILES includes it. Set both, or neither: with only PUBLIC_URL, the emails link to a website that isn't running.

To switch a running copy to email-only, stop the website first with docker compose --profile web stop web, then clear both settings and run docker compose up -d. Reports already saved expire as usual.

Changing how Docker runs it

Everything is set in .env, so you shouldn't need to edit docker-compose.yml. To change how Docker runs it on your host (joining a network, a reverse proxy's labels, a bind-mounted data folder, logging), put those changes in a docker-compose.override.yml next to it. Compose merges it in automatically, and git ignores it.

To run more than one copy on the same host, give each its own folder (a separate clone, with its own .env), CONTAINER_NAME and WEB_BIND. Compose names each copy after its folder, which keeps their services and data apart. If two folders have the same name, give one a project name of its own with COMPOSE_PROJECT_NAME in its .env.
