{{ app_title }} tells you whether a domain's email is set up properly. Send one email to {{ m.address(v) }} and you get a report back: can the domain send and receive email, and does its mail pass the authentication checks (SPF, DKIM and DMARC) that receiving servers use to decide what to trust.

It's meant for the people who look after a domain's email. Send the test from the mail system you want to check, and the report shows what a receiving mail server sees.

How it works

  1. Send a test email

    From any mailbox on the domain you want to check, send an email to {{ m.address(v) }}. The subject and text don't matter (though some mail programs won't send a message with a blank subject).

  2. Get the report by email

    A reply with the report arrives at the address you sent from, usually within {{ m.within(v) }}.

  3. Or view it online

    Enter the address you sent from on the home page to see the same report here, handy if the reply can't reach you. Reports online don't last: see View a report online.

What you get

Every report starts with a summary: three plain answers and an overall status.

{{ m.overview(examples["passed"], titled=True) }}

Below the summary, the report has a box for each check:

  • PTR: does the sending server's IP address have a name that points back to it?
  • SPF: does the domain allow that server to send its mail?
  • DKIM: is the message signed with a key the domain publishes?
  • DMARC: does the domain publish a policy, and did SPF or DKIM pass for it?

Checks that don't pass explain why, and problems with a record are pointed out. The emailed report also has the summary as a picture, ready to share, and the message's full headers.
